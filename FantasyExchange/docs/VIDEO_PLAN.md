# Required recordings

These are recording plans. The students must record the actual videos, and each student must appear in the music video.

## Software demo, about three minutes per student

0:00-0:20: State the project name, explain virtual player shares, and identify the simulated data.

0:20-0:50: Search for a player, use a position filter, and cycle the sort options. Select a player and explain the four-week points chart.

0:50-1:30: Buy two shares. Show the balance, holdings, and recorded purchase prices. Advance one simulated week and explain the changed quote and portfolio value.

1:30-2:00: Sell one share and open History. Point out that the receipt keeps its execution price. Show how an empty or unaffordable action is disabled.

2:00-2:30: Create or switch a local profile, show the shared market and League, then reopen the app to demonstrate saving.

2:30-3:00: Show one short method in source and explain it without reading a script. Finish with the two-dimensional stats array and one ArrayList.

Before recording, use a separate save file so rehearsal does not change the demonstration season. Do not claim to have tested a feature unless you actually show or test it.

## Music video

Choose a short school-appropriate track you are permitted to use. Record each student on camera, with some clips of the program between appearances. A simple structure is opening title, one appearance per student, market/trading clips, and a final group shot. Keep the music-video editing separate from the plain software demo.

## Before submission

Compile from a clean folder. Run the app on the classroom computer. Test the search, profile, and next-week dialogs. Confirm each student has a 2-4 minute software demo and appears in the music video. Submit the source, README, UML, code review presentation, and both required kinds of video. Check the teacher's specific upload locations and naming requirements.
